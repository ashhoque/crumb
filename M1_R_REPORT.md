## Result

Pruvello can now retain intention and problem understanding before proposing a
build. A raw idea no longer needs a fabricated feature or learning proposal to
fit the storage contract. The skill first clarifies or accepts skipped intention,
reframes the problem and gives a short evaluation; Build now remains available
throughout. An unanswered question does not mean a request to build.

The stock rehearsal now asks whether the tool is personal or commercial, identifies
the difficulty weighing conflicting notes, and considers uncertainty about existing
substitutes. When the synthetic founder says “Build now; skip research,” it proposes
a small comparison and leaves approval pending until that scope is accepted.

## What changed

- Added version-3 orientation/proposal drafts. Orientation has no proposal/decision
  and cannot be approved for implementation. Intention records provided, unasked,
  asked or skipped; a short assessment is distinct from research availability.
- Kept complete scope for actionable drafts. A recorded explicit build request
  bypasses business-context prerequisites. Otherwise intention, problem and a brief
  evaluation precede an action recommendation. Decisions remain host reports.
- Added orientation rendering/resume, optional detail and bounded question slots.
  Default replies retain 2–5 summary sentences and the existing 120-word ceiling.
  Optional detail is bounded; no research or detail view creates approval.
- Centralized runtime display branding in `src/domain/brand.ts`. Added `$pruvello`
  with one maintained set of references; `$pruvity` and `$customer-evidence` forward
  to it. Legacy explicit probe markers remain available through their aliases.
- Added four synthetic orientation fixtures and twelve regression tests. The
  feedback correction changes the problem from overdue ordering to missing
  follow-up history, rather than reusing the same proposed feature.
- Added active `PRODUCT_SPEC.md` v0.6, updated PLAN/AGENTS/current guides and ADR 0006.
  The revised roadmap is M2 deep Evaluate, M3 staged Act, M4 Launch & Learn and M5
  evidence-earned improvements. Privacy/recovery gates must precede real data even
  when milestone numbering changes. Commercial work remains unscheduled.
