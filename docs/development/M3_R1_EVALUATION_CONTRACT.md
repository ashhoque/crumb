# Focused M3-R1 evaluation contract

`src/domain/evaluation-quality.ts` defines the optional backward-compatible
`IdeContext.quality` extension. `internal schema` exposes it; `internal template`
includes an unexamined quality object for fresh native conversations. `evaluation-plan`
returns current user/problem, responsibilities, technical topics and the template.
It is a read-only research plan, not a research execution claim.

The host fills:

- `technical`: material flag, summary, central risk, ten topic rows, at most three
  options and one recommendation. Each row has status, claim/run references and a
  relevance/limitation explanation. Findings need claims; completion needs retained
  actual attempts for relevant topics and no unexamined rows. Existing-project
  completion also needs permitted repository artifacts with normal hash checks.
- `founderFit`: reported/supported edge, limits and claim references. Lack of a
  demonstrated edge is a valid conclusion; don't infer experience from an identity.
- `learning`: important uncertainty, reason and research/interview/build-decision
  recommendation. Behavioral uncertainty cannot be silently marked resolved by a
  build recommendation. The existing final Act choice remains available after review.

Normal saves reject dropping an existing quality contract. Quality belongs to
the Evaluation basis: edits retire its review and Act readiness, preserving valid
Intention/User/Problem. No historical confirmation or schema is rewritten merely
because this extension exists. Legacy contexts remain compatible; host instructions
adopt quality for new or materially refreshed research.

The deterministic question guard catches common API/database/competitor/community/
pricing-model questions delegated to the founder. It is deliberately conservative,
not exhaustive semantic enforcement. Founder constraints and intent remain allowed.
The host must reason about relevance and truth; references cannot prove a claim.

`detail --section technical` exposes paginated findings. Compact context retains
only summary/risk/founder-fit/learning plus a detail reference. The deeper research
artifact retains quality and sources. The existing Build Pack carries these limits
and prompts the smallest manual/existing-tool alternative before more automation.

`interview-followup` accepts a minimized answer, returns one suggested past-behavior
question and `recorded:false`. It is not an evidence-import or messaging endpoint.
Discovery rendering ignores freeform pitch questions and retains the five concepts.
