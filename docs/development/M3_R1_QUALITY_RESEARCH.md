## Methodology checked against primary sources

- [YC recap: Eric Migicovsky](https://www.ycombinator.com/blog/startup-school-week-1-recap-kevin-hale-and-eric-migicovsky/):
  use the person's actual experience, a recent occurrence, difficulty, attempted
  remedies and dissatisfaction. This supports the corrected five-concept guide
  and answer-led follow-ups, not hypothetical product/purchase prompts.
- [Kevin Hale discussion](https://www.ycombinator.com/blog/startup-school-podcast-preview-with-kevin-hale):
  problem size/direction, urgency, expense, necessity and recurrence are useful
  lenses; an opportunity need not satisfy every lens. Crumb retains judgment and
  uncertainty instead of inventing a score.
- [YC essential advice](https://www.ycombinator.com/blog/ycs-essential-startup-advice/):
  narrow early scope, direct user learning and manual work can accelerate useful
  learning. The Build Pack now explicitly considers an existing-tool/manual path
  before more automation. It does not add another approval stage or business model.

## Consequence for the rehearsal

Crumb recommends interpreting the initial comparison around dated supplied facts
and consistent reasoning. Automated licensed feeds remain an option needing actual
rights, cost and reliability checks; public quarterly holdings are background only.
This is a feasibility judgment, not a feature scope before Act. The confirmed
scheduled-review pain and commercial intent remain hypotheses for direct learning.

The strongest founder edge is **reported** workflow experience, coding ability and
possible access to two traders in the synthetic scenario. It is not established
distribution, proprietary data, paid demand or an unfair advantage. Interviews are
recommended around real comparison behavior. A scripted intent clarification then
exercises the Define/Evaluate confirmation loop; it is not a fabricated user finding.

Unresolved: current permission to recruit in the community, firsthand customer
behavior, actual commercial-data contract/cost, API integration, latency/reliability,
deployment security and willingness to pay. No winning-trade prediction is claimed.
