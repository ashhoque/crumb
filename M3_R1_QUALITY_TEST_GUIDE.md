# Focused M3-R1 founder trial

Use a disposable customer project, not Crumb's development repository. Invoke the
current repository skill explicitly. This is an unscripted experience check; the
automated rehearsal cannot establish whether Crumb feels enjoyable to you.

1. Describe an idea you understand. Give a preferred name only if you want.
   Answer a current confirmation with “yup”, “sounds right”, then “maybe” once.
   Expect natural progression, occasional name use, and one warm clarification
   for ambiguity. Known context should be proposed, not requested again.
2. For stocks, explain the scheduled shortlist comparison pain. If asked which
   API/database/community to choose, record that failure. Crumb should investigate
   first, explain delayed holdings/data rights plainly, and check product intent.
3. Before Act, look for a short competitor strength/friction/gap synthesis and a
   specific source-supported first-user avenue without asking for either. Open
   technical detail once, then continue without reading the remaining dossier.
4. If real behavior remains uncertain, expect an interview recommendation. Open
   the guide: difficulty → latest occurrence → why → tried approaches → dislikes.
   Offer one past-workaround answer; expect a relevant follow-up, not a product pitch.
5. Correct the problem. Expect only affected definitions/research to reopen. If
   you choose to build without interviews, confirm the current Act commitment.
   The handoff should preserve all confirmed context and stop before coding.
6. In a build-capable session with the actual same project files, say **Continue
   the Crumb build.** Expect the six-document pack, bounded scope and review before
   execution. A ChatGPT text instruction is not a native shared-files integration.

Report only what felt repetitive, confusing, too formal, or unnecessarily handed
back to you. Do not provide real contact details or private customer notes for this
trial. Outreach stays founder-controlled. Stop after the intended review point;
this guide does not authorize another milestone, payment, deployment or rollout.
